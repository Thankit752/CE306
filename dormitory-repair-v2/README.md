## ระบบคิวทำงานยังไง (`server/slots.js`)

- **ช่องเวลา:** วันละ 4 ช่อง ช่องละ 2 ชม. (08–10, 10–12, 13–15, 15–17) จองล่วงหน้าได้ 7 วัน
- **ช่องหนึ่ง "ว่าง"** เมื่อมีช่างอย่างน้อย 1 คนที่
  1. อยู่ในเวลางานตลอดช่องนั้น
  2. ยังไม่มีงานในช่องนั้น
  3. งานของวันนั้นยังไม่ถึงโควตา `max_jobs_per_day`
- **ตอนกดจอง:** `bookRequest()` เปิด `BEGIN IMMEDIATE` (ล็อกการเขียน) → เช็กช่างว่างอีกครั้ง → เลือกคนที่งานวันนั้นน้อยสุด → INSERT → COMMIT
  - ถ้าระหว่างนั้นช่องเต็มแล้ว → ตอบ **409 "ช่องเวลานี้เพิ่งเต็ม"**
- **ชั้นสุดท้าย:** `CREATE UNIQUE INDEX ... ON requests(assigned_staff_id, slot_date, slot_start) WHERE status IN ('pending','in_progress')` ต่อให้โค้ดมีบั๊ก ฐานข้อมูลก็ไม่ยอมให้ช่างคนเดียวมี 2 งานในช่องเดียวกัน
- **ยกเลิกคิว** → status = cancelled → ช่องว่างให้คนอื่นจองทันที
- **แอดมินย้ายช่าง** ได้เฉพาะไปหาช่างที่ว่างในช่องเดิม (ไม่เลื่อนเวลา ไม่แซงคิวใคร)
- **ปรับเวลางาน/โควตาช่าง** มีผลกับการจองใหม่เท่านั้น คิวที่จองไปแล้วไม่ถูกเลื่อน

### ผลทดสอบจริง

| ทดสอบ | ผล |
|---|---|
| 3 คนกดจองช่องเดียวกันพร้อมกัน (มีช่างว่าง 2 คน) | 2 คนได้คิว (คนละช่าง) · คนที่ 3 ได้ 409 · ช่องนั้นขึ้น "เต็ม" |
| จองวันเดียวกัน 8 ครั้ง (ช่างรับได้รวม 3+2 = 5) | ได้ 5 คิวพอดี · สมชาย 3/3 · สมหญิง 2/2 · ที่เหลือ 409 |
| ยกเลิก 1 คิว แล้วจองช่องเดิมใหม่ | ช่องกลับมา "ว่าง 1" · จองใหม่ได้ทันที |

## ความปลอดภัย

| ป้องกันอะไร | ทำยังไง |
|---|---|
| อัปโหลดไฟล์ HTML ปลอมเป็นรูปเพื่อขโมยสิทธิ์แอดมิน (XSS) | นามสกุลมาจากรายการที่กำหนด · ตรวจ magic bytes ต้นไฟล์ · ส่ง header `nosniff` |
| ส่งข้อมูลผิดรูปแบบให้ server พัง | `validate.js` ตรวจชนิดก่อนใช้ → ตอบ 400 |
| ปลอมสถานะย้อนกลับ ทำ KPI เพี้ยน | สถานะเดินหน้าได้ทีละขั้นเท่านั้น (รอคิว → กำลังซ่อม → เสร็จ) |
| ช่างถูกลบแล้วยังใช้ token เก่า | middleware อ่านผู้ใช้จากฐานข้อมูลทุก request |
| ลืมตั้ง JWT secret ตอน deploy | `NODE_ENV=production` แต่ไม่มี `JWT_SECRET` → server ไม่ยอมเปิด |

## API

| Method | Endpoint | สิทธิ์ |
|---|---|---|
| POST | `/api/auth/register`, `/api/auth/login` | ทุกคน |
| GET | `/api/auth/me` | ล็อกอินแล้ว |
| GET | `/api/slots` | ล็อกอินแล้ว — ตารางช่องว่าง 7 วัน |
| POST | `/api/requests` | student — จองช่อง + แจ้งซ่อม (409 ถ้าเต็ม) |
| GET | `/api/requests`, `/api/requests/:id` | กรองตาม role |
| PUT | `/api/requests/:id/status` | staff, admin |
| PUT | `/api/requests/:id/reassign` | admin — ย้ายช่างในช่องเดิม |
| DELETE | `/api/requests/:id` | student (เจ้าของ), admin — ยกเลิก |
| CRUD | `/api/staff`, `/api/repair-types` | admin |
| GET | `/api/stats` | admin — KPI + ภาระงานช่าง 7 วัน |

## KPI (หน้าแอดมิน)

1. **เวลาเฉลี่ยจนซ่อมเสร็จ** — AVG(completed_at − created_at)
2. **อัตราใช้คิวช่าง 7 วัน** — งานที่จอง ÷ งานที่ช่างทุกคนรับได้ (เกิน 90% = ควรเพิ่มช่าง)
3. **API ตอบสนองเฉลี่ย** — เป้า < 500ms
